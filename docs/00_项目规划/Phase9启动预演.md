# Phase9 启动预演

## 1. 预演结论

- 决策：**Conditional Go**。
- Phase9 可在当前隔离分支继续推进，但必须遵守本预演门禁与项目根目录 `AGENTS.md` 的长期治理规则。
- P9.1 已完成开发、架构审查和测试验收；P9.2 可在本预演记录生效后启动。
- 当前工作基于 Phase8 堆叠基线，禁止直接合并主分支；须等待前序 Phase 的提交和合并顺序明确。

## 2. 产品范围与禁止项

### 本阶段范围

- V3 多页面模型、页面生命周期与设计态页面切换。
- 页面创建、复制、删除、排序和默认页管理。
- 受控事件模型、事件编排基础能力与安全运行时。
- 多页面与事件能力的定向测试、E2E 和阶段验收。

### 本阶段禁止项

- 页面导航、钻取、弹窗、打开外链等 Phase10 交互能力。
- 发布流程、权限体系、生产部署和 AI 能力扩展。
- 未冻结契约的跨页面事件传播或跨页面刷新。
- 将设计器会话状态写入 Dashboard 持久化模型。
- 为赶进度直接在主分支开发或绕过架构、测试门禁。

## 3. 前置依赖与代码基线

- 基线 commit：`73d5fba`（Phase8 堆叠基线）。
- 工作分支：`agent/phase9-multipage-events`。
- 主分支仍落后于当前堆叠基线；Phase9 只允许本地隔离开发，不得擅自 push、merge 或改写历史。
- Phase7、Phase8 的提交与合并顺序是 Phase9 最终进入主分支的前置条件，不阻断本地实现和验收。

## 4. 模块边界与兼容目标

- `pageManagerV3` 保持纯领域能力，负责页面增删复制、排序、默认页约束和引用改写。
- `activePageId` 属于设计器会话状态，不进入 V3 Dashboard 持久化契约。
- 页面 UI、会话适配和事件运行时分别落在独立模块，避免继续扩大 `DesignerHome` 的职责。
- 事件持久化动作当前仅允许 `setParameter` 与 `refresh`；旧 `dialog` 数据仅保证可读取，不允许新建。
- Refresh 只能作用于事件所属页及所属页内组件。
- 保持 V1/V2/V3 既有读取与迁移兼容，不破坏 Phase8 已验收能力。

## 5. 环境条件

- Node.js 22 与项目既有前端测试、构建环境必须可用。
- Chromium/E2E 环境在 P9.2 节点关闭和 Phase9 综合验收时使用。
- 本地 PostgreSQL 测试环境已就绪。连接地址、账号和凭据只允许通过本地环境变量或临时命令输入，不写入仓库、日志和测试快照。
- Phase9 当前不改变数据库 Schema 或持久化数据库契约，日常定向测试不依赖 PostgreSQL；仅在确有数据库链路回归需求时启用。

## 6. 核心风险与控制措施

| 风险 | 级别 | 控制措施 |
| --- | --- | --- |
| 事件递归、循环传播或重复触发 | P0/P1 | 深度上限、事务标识、同值去重、异常中止与专门测试 |
| 页面复制后 ID、刷新目标或组件引用悬空 | P1 | 复制时统一重写引用，删除时校验引用，覆盖异常路径测试 |
| 设计态状态混入持久化模型 | P1 | `activePageId` 仅存会话层，Schema 和序列化测试设门禁 |
| Refresh 越过页面边界 | P1 | 运行时强制限制为事件所属页及所属页内组件 |
| 页面切换造成未保存编辑丢失或选择串页 | P1 | 切换前保存当前页草稿，切换后重置或隔离组件选择 |
| `DesignerHome` 继续膨胀导致核心耦合 | 高 | 页面面板、会话适配、事件运行时拆分独立模块并接受架构审查 |
| 多窗口并行修改同一代码 | 高 | 仅开发主窗口写业务代码；架构与测试窗口只审查和验证 |
| 堆叠分支合并顺序错误 | 高 | Phase9 禁止直接合并主分支，最终放行时核对前序 Phase 顺序 |
| 多窗口重复全量测试造成额度浪费 | 中 | 日常只跑定向测试；节点关闭或核心公共模块变化时才跑全量/E2E/生产构建 |
| 本地凭据泄露 | P1 | 不写入代码、文档密码字段、命令历史输出、日志或提交；只引用连接条件 |

## 8. 测试策略与证据归属

- 开发窗口：每个节点执行受影响范围的单元/集成测试并记录命令、结果和修改文件。
- P9.2 节点关闭：执行页面操作定向测试、设计器页面切换 E2E 和生产构建；同一证据不由多个窗口重复执行。
- 事件运行时节点：重点覆盖递归深度、去重、异常隔离、非法目标和跨页阻断。
- 测试窗口：基于目标 diff 和验收清单执行正式定向验收，负责节点测试结论。
- 架构窗口：审查公共契约、持久化边界、运行时边界和 `DesignerHome` 关键差异。
- 项目经理：汇总开发、架构、测试证据，决定 accepted、conditional accepted 或 blocked。
- Phase9 最终关闭前执行一次全量测试、E2E 和生产构建，不在小步骤之间重复执行。

## 9. 回滚方式

- 所有 Phase9 变更保持在隔离分支，未获批准不得进入主分支。
- 节点变更应保持范围清晰，便于按节点提交或反向变更；禁止使用破坏性 reset 清理用户工作区。
- Schema 或公共契约变更必须同时保留兼容读取路径和迁移测试，回滚时不得破坏既有 V1/V2/V3 数据。
- 若出现 P0/P1，立即停止后续节点，保留失败证据，由架构窗口确认修复或回滚方案后再恢复。
