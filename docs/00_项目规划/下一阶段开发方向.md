# 下一阶段开发方向

Phase10 和通用设计器增强已经完成并进入远端 `main`。项目后续定位为可嵌入业务系统的轻量 BI 设计与运行内核，不再默认进入原 Phase11 发布、权限和完整治理路线。

## 权威路线

2026-08-26 已确认 [医疗 BI AI 知识资产与智能分析路线规划 V2](../05_AI规划/医疗BI_AI知识资产与智能分析路线规划_V2.md)，后续采用四条工作流：

- `KA`：医疗 BI 知识资产。
- `TG`：看板模板与 AI 草稿生成。
- `DM`：数据挖掘。
- `MR`：模型运行、本地模型/云 API 适配和能力评测。

总体顺序为：

```text
KA0 规范冻结
→ KA1 单场景纵向样板
→ KA2 三场景MVP
→ KA3 校验、注册与混合检索
→ TG1 模板Blueprint
→ TG2 AI自动看板草稿
→ IA1 AI与数据挖掘闭环
```

`DM0/DM1` 在 KA0 完成后可与知识资产建设并行；`MR0` 作为 KA0 的横切规划内容同步冻结，但不立即接入真实模型。

上下文和多用户聊天记忆使用 `CM` 工作流记录。KA0 只预留 `ContextEnvelope` 和隔离边界；本地 MVP 只做单用户临时会话上下文，持久化聊天、长期记忆和多用户隔离在集成部署后按真实需求启动，不阻塞知识资产、模板和数据挖掘验证。

## 当前边界

- 当前只确认路线，不自动启动 KA0 或功能开发。
- PostgreSQL/Greenplum 继续作为当前数据库重点。
- MySQL、Oracle 暂不开发，只保留未来扩展位。
- 权限中心由宿主业务系统负责，BI 只预留权限上下文接口。
- 独立发布、完整治理和生产运维作为需求触发型 Backlog。
- 私有医疗知识、真实 SQL、业务模板和数据库信息不进入公开仓库。
