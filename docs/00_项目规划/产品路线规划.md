# 医疗BI Designer V2.0 开发顺序调整方案

## 一、文档定位

本文档是医疗BI Designer V2.0 后续开发的唯一阶段顺序基线。

当前 MVP 已具备：

- 三栏设计器
- 组件拖拽
- 属性配置
- JSON 保存
- PostgreSQL 数据连接
- 数据集绑定
- 基础医疗看板

V2.0 的目标不是继续堆叠零散功能，而是将现有看板工具升级为可持续扩展的医疗BI低代码设计平台。

目标链路：

```text
数据源 → 数据集 → 字段 → 指标 → 组件 → 页面 → 模板
```

## 二、开发原则

优先保证：

1. 数据模型稳定。
2. 组件模型可扩展。
3. JSON 可持续升级。
4. 数据集、指标、组件形成完整闭环。
5. 每个阶段经过验收后，才能进入下一阶段。

已有但尚未经过对应阶段正式验收的代码，统一标记为“预实现”，不得视为阶段完成。预实现代码保留，但必须在对应阶段重新审查、测试和输出验收材料。

## 三、阶段闸门

严格按照以下顺序开发：

```text
Phase0 → Phase1 → Phase2 → Phase3 → Phase4 → Phase5 → Phase6
```

阶段通过条件：

- 本阶段功能清单全部实现。
- 构建和自动化测试通过。
- 浏览器功能验证通过。
- 本阶段规定的交付材料齐全。
- 已记录遗留风险，不存在阻塞下一阶段的数据模型问题。
- 用户确认本阶段验收通过。

说明：

- Phase0—Phase5 分别进行模型、功能和页面级验收。
- Phase6 使用真实 ODR 数据进行全链路综合验收。
- Phase6 不替代前面各阶段的基础验证。

## 四、开发阶段

### Phase0：JSON 模型兼容设计

#### 目标

建立稳定、可演进、可迁移的看板 JSON 模型，避免升级后已有看板无法打开。

#### 实现范围

- 盘点当前 JSON 结构。
- 设计 V2 JSON 结构。
- 明确 V1/V2 兼容方式。
- 建立 `version` 版本机制。
- 建立数据迁移方案。
- 对缺失字段提供默认值。
- 对历史配置执行非破坏性迁移。

#### 验收重点

- V1 看板可在 V2 中正常打开。
- V2 看板保存后可再次加载。
- 未知字段不导致页面崩溃。
- 迁移过程不覆盖原始业务配置。

### Phase1：数据计算底座修复

#### 目标

统一字段聚合、分组、系列拆分和排序规则，为所有组件提供一致的数据计算结果。

#### 排序

支持：

- 升序
- 降序
- 无排序

排序必须作用于最终展示数据，并明确维度排序和指标排序的优先级。

#### 分组

支持：

- `GROUP BY`
- 第二维度拆分系列

#### 聚合

支持：

- `SUM`
- `AVG`
- `MIN`
- `MAX`
- `COUNT`
- `COUNT DISTINCT`
- `NONE`

字段约束：

- `SUM`、`AVG` 仅支持数值字段。
- `COUNT` 支持字符串、数值和日期字段。
- 不适用的聚合方式不得在界面中提供，后端仍需执行二次校验。

#### 验收重点

- 字符串字段 `COUNT` 正常。
- 数值字段各聚合结果正确。
- `COUNT DISTINCT` 去重正确。
- 第一维度分组正确。
- 第二维度能够形成独立系列。
- 升序、降序、无排序结果正确。
- 表格、指标卡、图表使用同一套计算语义。

### Phase2：组件模型拆分

#### 目标

解决所有组件共用同一套配置的问题，形成公共配置和组件专属配置的稳定边界。

#### 公共配置

- 标题
- 位置
- 尺寸
- 基础样式

#### 指标卡专属配置

- 主指标
- 单位
- 同比
- 环比
- 目标值
- 进度条

#### 图表专属配置

- X 轴
- Y 轴
- 系列
- 标签
- 图形类型

#### 表格专属配置

- 列
- 宽度
- 排序
- 格式
- 汇总

#### 验收重点

- 表格和指标卡不显示无意义的轴、线配置。
- 切换组件类型时保留公共配置。
- 不适用的专属配置不参与查询和渲染。
- JSON 中公共配置和专属配置边界清晰。

### Phase3：指标卡能力完善

#### 目标

完善医疗驾驶舱常用指标卡能力。

#### 实现范围

- 指标配置
- 自定义单位
- 小数位
- 千分位
- 同比
- 环比
- 上升、下降颜色
- 目标值
- 达成率
- 进度条

#### 验收重点

- 主指标、同比、环比可分别绑定字段。
- 单位、小数位和千分位格式正确。
- 同比、环比方向和颜色可配置。
- 达成率计算规则明确并处理目标值为零的情况。
- 进度条能够正确反映目标达成情况。

### Phase4：图表增强

#### 目标

完善常用分析图形、多指标和动态辅助分析能力。

#### 气泡图

支持：

- X 轴
- Y 轴
- 气泡大小

#### 组合图

支持：

- 柱形图
- 折线图
- 面积图
- 多指标映射
- 双 Y 轴独立配置

#### 坐标轴

支持：

- 最大值
- 最小值

#### 预警线

支持：

- 固定值
- 平均值
- 最大值
- 最小值
- 中位数
- P80
- P90
- P95
- 指标字段
- 目标值字段

#### 数据标签

支持：

- 原始值
- 百分比
- 原始值和百分比
- 小数位
- 单位

#### 验收重点

- 图形配置随图表类型变化。
- 双 Y 轴的数据选择、样式和交互配置相互独立。
- 多维度、多指标字段映射正确。
- 动态预警线随筛选结果重新计算。
- 百分比标签的分母规则明确且结果正确。

### Phase5：参数、联动、下钻

#### 目标

建立统一参数体系，使数据集、控件和组件能够联动。

#### 参数控件

- 按钮组
- 单选
- 多选
- 日期
- 日期区间

#### 统一参数

- `year_code`
- `month_code`
- `dept_code`
- `b_date`
- `e_date`

#### SQL 参数

支持帆软类似的条件表达能力，例如：

```text
${if(len(dept_code)=0,""," and dept_code='"+dept_code+"'")}
```

实现时必须使用受限表达式解析器和参数绑定机制，不直接执行任意字符串代码。参数名称、函数、运算符和输出片段需受白名单约束，并继续执行只读 SQL 安全校验。

#### 联动

- 点击组件传递参数。
- 接收参数的其他组件自动刷新。
- 参数来源、目标和刷新范围可配置。

#### 下钻

支持：

```text
医院 → 科室 → 医生
```

#### 验收重点

- 参数默认值和空值语义一致。
- 多选和日期区间能正确传入查询。
- 联动不会形成循环刷新。
- 下钻路径、返回上级和面包屑状态正确。
- SQL 参数不能绕过只读查询限制。

### Phase6：真实数据验证

#### 固定验证数据源

- 数据源名称：`odr`
- 主机：由本机私有配置提供
- 端口：`1579`
- 数据库：由本机私有配置提供
- 用户：只读账号，由本机私有配置提供
- 默认 Schema：由本机私有配置提供

敏感凭据不得写入仓库或看板 JSON。

#### 趋势分析

验证：

- 排序
- 聚合
- 标签

#### 排名分析

验证：

- TOP 排序
- 分组

#### 组合图

验证：

- 双轴
- 数据映射

#### 指标卡

验证：

- 同比
- 环比
- 目标值

#### 验收重点

- 使用真实 ODR 查询结果，不使用前端模拟数据替代。
- 页面显示结果与校验 SQL 结果一致。
- 保存看板后重新打开，配置和结果保持一致。
- 数据集、指标、组件、页面形成完整链路。

## 五、每阶段交付物

每个 Phase 完成后必须输出：

1. 修改说明
2. 修改文件列表
3. 数据模型变化
4. 页面截图
5. JSON 示例
6. 测试结果
7. 下一阶段风险

交付材料建议存放在：

```text
docs/phase-deliverables/phase0/
docs/phase-deliverables/phase1/
docs/phase-deliverables/phase2/
docs/phase-deliverables/phase3/
docs/phase-deliverables/phase4/
docs/phase-deliverables/phase5/
docs/phase-deliverables/phase6/
```

## 六、当前状态重新校准

| 阶段 | 当前状态 | 处理原则 |
|---|---|---|
| Phase0 | 已实现，待按本方案整理正式交付包 | 补齐七项交付材料并确认阶段闸门 |
| Phase1 | 核心代码已实现，待正式验证 | 当前唯一执行阶段，优先验证排序、分组、聚合和系列拆分 |
| Phase2 | 存在部分预实现 | 暂不计为完成，Phase1 通过后重新审查 |
| Phase3 | 存在部分预实现 | 暂不计为完成，按阶段清单重新验收 |
| Phase4 | 存在部分预实现 | 暂不计为完成，缺失项继续补齐 |
| Phase5 | 未正式开始 | Phase4 通过后启动 |
| Phase6 | 未开始 | 前六个阶段完成后执行真实 ODR 综合验收 |

## 七、最终目标

形成医疗BI低代码设计平台，核心能力包括：

- 数据集体系
- 指标体系
- 组件体系
- 参数体系
- 联动体系
- 模板体系

目标能力范围：接近帆软 FVS 的 60%—70%，并优先保证医疗业务常用能力的稳定性、可配置性和可维护性。
