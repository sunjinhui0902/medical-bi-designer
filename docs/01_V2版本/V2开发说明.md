# 医疗 BI Designer MVP 实施计划

本项目用于验证一款独立的医疗 BI 低代码设计器。核心闭环是将只读 PostgreSQL 数据通过数据集查询转为 JSON，再绑定到画布组件；V1 不接入 Odoo，也不建设登录、权限、多租户、发布、ETL 或指标治理。

## 技术方案

- 前端采用 Vue 3、TypeScript、Vite、Tabler UI 与 ECharts。
- 设计器状态采用 JSON 看板模型统一表达组件类型、位置、数据、样式和交互配置，保证后续可复制、导入导出和接入 Odoo。
- 后端将在 Step 5 引入，负责加密保存 PostgreSQL 连接信息、执行连接测试及受限的只读 SQL；浏览器不直接连接数据库。
- 查询安全采用只读数据库账号、只允许单条 `SELECT`、服务端超时与返回行数上限等多层约束。

## 开发任务拆解

| 阶段 | 交付内容 | 阶段验收 |
| --- | --- | --- |
| Step 1 | Vue 3 工程、Tabler、ECharts、基础路由和页面框架 | 首页可访问，构建成功，折线图正确显示 |
| Step 2 | 左侧组件库、中间画布、右侧五类属性配置的三栏结构 | 桌面端三栏完整，基础响应式可用 |
| Step 3 | 组件添加、选择、移动、缩放、删除和布局持久化 | 操作可用，布局能序列化为 JSON |
| Step 4 | 看板、组件和数据集绑定模型，导入导出及本地保存 | KPI、图表、表格可消费统一数据结果 |
| Step 5 | PostgreSQL 数据源、数据集、连接测试和 SQL 预览 API | 只读查询全链路通过，危险 SQL 被拒绝 |
| Step 6 | Demo 表和医院运营概览看板 | 总收入、门诊量等指标与趋势、排名图表使用真实 Demo 数据 |

每个阶段完成后必须记录完成内容、截图、代码状态、已知问题和下一步建议；截图验证通过后再进入下一阶段。

## 边界与默认约定

- 当前版本仅使用 Demo 数据，不接触医院生产数据。
- Step 1 页面中的趋势图只验证 ECharts 集成，不代表真实数据绑定已经完成。
- “进入设计器”按钮在 Step 2 前保持禁用，避免暗示未实现功能可用。
- PostgreSQL 密码不得写入看板 JSON、浏览器存储或版本库。
