# Step5.1 真实数据集绑定验收记录

## 完成内容

- Designer 同时支持 Mock 数据集和服务端 PostgreSQL / Greenplum 数据集。
- 右侧数据配置增加“数据库数据集”入口。
- 新增独立数据集目录弹窗，不使用不可扩展的超长下拉框。
- 数据集目录支持名称、备注和字段搜索。
- 支持按数据源筛选。
- 支持服务端分页，并显示总数、当前页和每页数量。
- 数据集卡片展示数据源、字段数量、字段摘要和备注。
- 选择数据集后自动选择优先维度和数值指标。
- 真实数据执行结果可以驱动指标卡、折线图、柱状图、饼图和表格。
- 组件增加加载中、执行失败和手动刷新状态。
- 看板 JSON 保存 `sourceKind`、`datasetId`、`dimension` 和 `field`，不保存数据库密码。
- 刷新页面后自动恢复真实数据绑定并重新执行只读查询。
- 旧版看板没有 `sourceKind` 时自动兼容为 Mock 数据。

## 大规模数据集规划

### 当前已落地

- 数据集目录和组件属性面板解耦。
- 服务端负责搜索、数据源过滤、排序和分页。
- 当前目录每页展示 12 个数据集，API 支持 1 至 100 条分页读取。
- 查询关键字覆盖数据集名称、备注和字段名称。
- 按更新时间倒序展示，最近维护的数据集优先。

### 后续扩展边界

当数据集从几十个增长到几百或几千个时，在现有目录模型上增加以下能力，不需要改动画布组件的数据绑定结构：

1. 业务域、主题和标签分类。
2. 收藏、最近使用和我维护的数据集。
3. 数据集生命周期状态：草稿、已验证、停用。
4. 字段中文名、业务定义、单位和默认聚合方式。
5. 数据集负责人、更新时间和质量状态。
6. 服务端全文索引与游标分页。
7. 权限过滤和数据集使用影响分析。

## 自动验证结果

- 数据集目录 API 返回 2 个数据集。
- `limit=1, offset=0/1` 分别返回不同数据集，分页有效。
- 搜索“下钻”后只返回“门诊下钻明细”。
- 按数据源列表显示“医疗 Demo 数据库”和“odr”。
- “门诊下钻明细”识别 46 个字段。
- 绑定 Greenplum 数据集后返回 200 行预览数据。
- 自动选择 `service_event_id` 为维度、`is_valid_service` 为数值指标。
- 指标卡显示 200 条，并标记“数据库数据集实时计算”。
- 保存并刷新后，真实数据集、维度、指标和 200 行结果完整恢复。
- `npm run build` 通过。

## 已知边界

- 当前指标计算默认对数值字段求和；下一大项如涉及指标语义，应增加聚合方式、单位和格式配置。
- 当前字段选择仍采用下拉框。单个数据集出现数百字段时，建议升级为可搜索的字段选择器。
- 当前查询预览最多返回 200 行，适合组件展示验证，不用于大规模明细导出。
- 当前数据集目录没有权限、标签和收藏功能，这些可在后续平台化阶段增加。

## 阶段结论

数据库、数据集、看板组件和看板 JSON 的完整链路已打通。按当前安排跳过 Step6 Demo 看板，待本阶段人工验收后再进入用户指定的下一大项。
