# Phase7 开发交接

当前代码具备可运行的 V2 数据与可视化底座，生产构建和现有 24 项自动化测试通过。Phase7 应采用“V3 外壳 + 默认活动页适配器”的渐进升级，不直接重构组件渲染、数据集 API 或查询引擎。

## 1. 当前代码架构分析

### 前端

前端采用 Vue 3、TypeScript、Vite、Vue Router、Tabler UI 和 ECharts。路由包含设计器、数据源管理和数据集管理三个页面。

设计器状态集中在 `DesignerHome.vue`，使用 Vue `ref` 和 `computed` 管理 `DashboardModelV2`。该文件同时承担组件库、画布交互、属性编辑、数据加载、模板管理、导入导出和本地保存，属于高耦合单体页面。V3 接入应先抽离存储、迁移和活动页适配，不应在 Phase7 同时拆分全部 UI。

当前看板保存于 LocalStorage：

- V2 草稿：`medical-bi-designer-dashboard-v2`
- V1 兼容草稿：`medical-bi-designer-dashboard-v1`
- 医疗组件模板：`medical-bi-designer-component-templates-v1`

导入、加载和保存都直接在 `DesignerHome.vue` 中完成。`migrateDashboard` 只输出 V2，且规范化过程中会丢弃未声明字段，不具备 Schema、迁移报告、备份和失败回退。

### 模型与计算

`models/dashboard.ts` 定义单页 `DashboardModelV2`；`models/bi.ts` 定义数据集、字段语义、指标引用和组件数据配置。`queryResult.ts` 在前端完成分组、聚合、排序、系列拆分和表格转换。

组件已经分离图表、指标卡和表格专属配置，现有测试覆盖排序、聚合、系列、指标卡、预警线、百分比和气泡映射。这是 Phase7 必须保护的回归基线。

### 后端

后端是 Node.js ESM 原生 HTTP 服务，使用 `pg` 连接 PostgreSQL/Greenplum。数据源和数据集元数据暂存于本机 JSON 文件，密码通过 AES-256-GCM 加密。API 支持数据源测试、数据集目录与维护、只读查询预览和数据集执行。

服务端目前执行已保存的静态 SQL，不接收看板参数，也没有数据集参数绑定、查询依赖图、缓存、看板版本或发布存储。该现状与 Phase7“后端零改动、数据库零 DDL”边界一致。

### 验证基线

- `npm run build` 通过。
- 7 个测试文件共 24 项通过。
- 构建提示 JavaScript Chunk 超过 500 KB，但不阻塞 Phase7。
- 项目 Git 当前无提交，全部项目文件仍是未跟踪状态。

## 2. docs 设计与当前代码差异

| 设计要求 | 当前代码 | 差异 |
| --- | --- | --- |
| V3 根模型、`pages[]`、默认页 | 只有根级画布和组件的 V2 | 未实现 |
| 应用 ID、页面 ID 使用稳定规则 | V2 根模型无 `id`、无页面 | 未实现 |
| V1 → V2 → V3 与 V3 幂等读取 | 只有 V1/V2 → V2 规范化 | 未实现 |
| JSON Schema 与可定位错误 | 无 Schema 依赖，导入只提示“格式无效” | 未实现 |
| 双读、单写 V3、旧草稿备份 | V2/V1 二选一读取，直接覆盖 V2 Key | 未实现 |

| 应用参数含 `code`、`source`、`validation` | 数据集参数只有 `id/name/type` 等简化字段 | 模型不足且 `text/string` 枚举不一致 |
| 活动页兼容层 | 组件直接访问 `dashboard.components` | 未实现 |

| README/版本状态反映 V2 完成 | README 仍写 Step1，包版本为 `0.1.0` | 文档状态漂移 |
| 固定验收地址 | 启动脚本 API 为 5175，旧文档同时出现 5174 | 需在实施前统一 |

另有两处设计冲突需要按文档优先级消解：

1. V3 整体架构曾将参数控件基础协议和视觉小修列入 Phase7；详细实施方案规定 `controls[]` 固定为空、视觉修复独立实施。Phase7 应以后者为准。
2. 整体模型示意包含 `publishConfig`，详细 Phase7 JSON 使用 `extensionRefs`。建议 V3 根类型保留可选 `publishConfig`，并将 `extensionRefs` 设为必需空对象，Phase7 两者均不执行运行逻辑。

## 3. Phase7 实施方案

### P7.0 基线冻结

- 固定 V1、V2、空白 V2 和大组件量样例。
- 集中记录现有 LocalStorage Key。
- 建立 V2 构建、24 项单测和人工回归基线。
- 在编码前建立可回退版本基线；当前仓库无提交，需用户确认后再创建提交。

### P7.1 V3 类型、默认工厂和 Schema

- 新建 V3 根模型、页面、参数、运行策略和扩展引用类型。
- 建立默认单页应用工厂，默认画布 `1200 × 600`。
- 建立 JSON Schema 和统一校验入口。
- 使用同一批有效/无效样例验证 TypeScript 默认工厂与 Schema。

### P7.2 迁移编排

- 保留当前 V1 → V2 迁移器。
- 新增纯函数 V2 → V3 迁移器。
- 新增版本识别、链式迁移和 V3 幂等处理。
- 输出迁移报告并验证稳定 ID、输入不变、敏感信息隔离和扩展字段处理。

### P7.3 存储与导入导出

- 建立存储服务，集中管理 V1/V2/V3 Key。
- 读取顺序为 V3、V2、V1、默认 V3。
- 首次迁移前备份旧草稿；新 V3 校验通过后才写入。
- 保存和导出只写 V3；导入接受 V1/V2/V3。
- 失败时保留现有有效草稿，并展示可定位的错误与迁移报告。

### P7.4 参数注册表

- 建立参数 CRUD、复制、模板注册和内置字典。
- 校验编码唯一性、类型、默认值、日期范围和静态选项。
- 保持应用参数与数据集查询参数类型分离。

### P7.5 参数中心页面

- 增加路由与导航入口。
- 实现搜索、新建、编辑、复制、删除和模板一键创建。
- 参数随 V3 草稿保存、导入和导出。
- 不触发数据集请求，不渲染参数控件。

### P7.6 设计器兼容层

- 通过 `activePage` 或等价适配器向现有组件层暴露画布、标题和组件数组。
- 将导入导出、保存和恢复切换到 V3 存储服务。
- 保持现有组件、数据绑定、画布与属性面板行为不变。

### P7.7 验收

- 完成 V1/V2/V3 迁移、Schema、存储、参数注册和兼容层自动化测试。
- 执行当前 24 项回归与生产构建。
- 人工验证迁移、刷新、导入导出、参数中心和设计器交互。
- 输出修改说明、文件清单、V3 示例、测试结果和风险。

## 4. 数据模型变化

```text
DashboardModelV2
├── canvas
├── titleStyle
└── components[]

              迁移
                ↓

DashboardApplicationV3
├── id / name / defaultPageId
├── parameters[]
├── pages[]
│   └── default page
│       ├── canvas
│       ├── titleStyle
│       ├── controls[]      Phase7 为空
│       ├── components[]    复用现有组件模型
│       └── pageEvents[]    Phase7 为空
├── theme
├── runtimePolicy
├── extensionRefs
```

Phase7 不修改 PostgreSQL 表，不修改数据集 API，也不把参数运行值、页面栈、下钻栈或查询缓存写入 V3 JSON。

## 5. 风险点

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| `DesignerHome.vue` 体积大、职责集中 | V3 改造容易扩散并造成回归 | 先抽服务与适配器，组件渲染保持不动 |
| 当前迁移器裁剪未知字段 | V2 扩展配置可能静默丢失 | 固定真实样例，记录未知字段并保留安全扩展 |
| V2 根模型无稳定 ID | 重复迁移可能产生重复页面 | 使用输入特征和固定命名规则生成稳定 ID |
| V3 Schema 与 TypeScript 漂移 | 合法性判断不一致 | 使用同一批有效/无效样例双重测试 |
| 应用参数与数据集参数同名 | 后续绑定模型混乱 | 分离类型、服务和存储语义 |
| 本地存储直接覆盖 | 迁移失败可能损坏草稿 | 先备份、再迁移、校验通过后写入 |
| Git 无提交且文件全未跟踪 | 缺少 V2 可回退基线 | 编码前检查忽略规则并由用户确认建立基线 |
| 端口文档不一致 | 人工验收可能访问错误服务 | 统一前端与 API 的固定端口和说明 |
| 前端 Chunk 约 1.34 MB | 加载性能和后续扩展压力 | 记录为非阻塞债务，Phase7 不顺带重构 |
| 视觉小修与架构任务混入 | 范围膨胀、验收口径模糊 | 使用独立 `UI-FIX-01` 分支和验收 |

## 开发确认点

确认进入编码后，建议严格从 P7.0 开始，不先制作参数 UI，也不修改后端。P7.0 的第一个外部决策是：是否先为当前 V2 状态建立 Git 基线提交。
