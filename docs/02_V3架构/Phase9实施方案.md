# Phase9 实施方案

> 状态（2026-08-12）：P9.0—P9.7 已完成本地实现、最终全量门禁和架构/测试双签，Phase9 正式 accepted；未提交、推送、合并，也未进入 Phase10。

## 1. 目标与原则

Phase9 在 Phase7 的 V3 应用模型和 Phase8 的可信查询运行时之上，建设多页面与事件交互基础。设计态 JSON 只保存可迁移的页面、组件、控件和事件配置；`activePageId` 属于编辑器/播放器会话状态，不进入 Dashboard V3 JSON。

本阶段保持以下边界：

- 页面操作由纯领域服务完成，不耦合 `DesignerHome`、Vue 组件或浏览器存储。
- 事件定义与执行分离；持久化模型只允许经过白名单的动作类型。
- 页面、组件、控件、事件和动作复制后使用新 ID，并重写复制页内部引用。
- 旧的合法单页面 V3 JSON、V1/V2 迁移与 Phase8 查询链路继续兼容。

## 2. 节点拆分

### P9.0 基线与架构冻结

- 核对 stacked 分支、工作区和 Phase8 验收基线。
- 盘点 V3 页面模型、迁移、存储、Designer 适配器和事件扩展点。
- 冻结 Phase9/Phase10 边界、测试门禁和开发合并规则。

### P9.1 页面契约与领域服务

- 将 Dashboard V3 从单页面限制升级为 `pages.length >= 1`。
- 校验默认页引用、页面 `id/code/order`、数组顺序及应用级实体 ID 唯一性。
- 定义事件、条件、值来源及 `SetParameter`、`Refresh` 持久化白名单。
- 提供页面新建、复制、删除、排序和设置默认页的纯领域服务。
- 禁止删除最后一页和直接删除默认页；复制时重建实体 ID 与页内刷新引用。
- 本节点不接入设计器 UI，也不执行事件动作。

### P9.2 多页面设计器接入

- 增加页面管理入口、页面列表和活动页切换。
- `activePageId` 由设计器会话状态维护，保存时仅持久化 V3 应用模型。
- 让画布、组件选择与配置面板基于活动页工作。

### P9.3 事件配置编辑

- 提供页面级和组件级事件配置入口。
- 编辑事件名称、条件、动作顺序、启停与防抖配置。
- UI 仅生成 P9.1 白名单契约，不允许自由表达式或任意脚本。

### P9.4 事件总线与事务

- 建立事件上下文、条件判断、值解析、动作顺序和事务标识。
- 按 `runtimePolicy.maxEventDepth` 防止递归与循环触发。
- 事件运行态、队列和错误状态不进入持久化 JSON。

### P9.5 SetParameter 动作

- 将事件赋值原子提交到 Phase8 参数运行时。
- 复用类型校验、去重、依赖图和刷新调度，不绕过参数中心。

### P9.6 Refresh 动作

- Refresh 仅允许作用于事件所属页及所属页内组件，不支持跨页刷新。
- 复用 Phase8 查询键、请求合并、缓存和强制刷新语义。
- 补充失效引用、循环深度和部分失败处理。

### P9.7 交付收口

- 完成领域、集成与 Chromium 关键路径测试。
- 更新示例、迁移说明、验收记录和交接文档。
- 执行全量测试、构建、E2E 与差异检查后进入评审。

## 3. Phase10 排除项

以下能力不属于 Phase9，P9.1 不为其提供执行器或提前接入：

- 页面导航、返回栈和下钻栈。
- 新窗口、弹窗、外部链接和跨应用跳转。
- 下钻、清除交互状态及参数携带策略。
- Phase10 动作类型及其运行时执行器。
- 发布快照、版本治理、权限、审计与 AI 能力。

Phase10 应在 Phase9 的事件事务、引用校验和多页面设计器稳定后另行冻结契约。
