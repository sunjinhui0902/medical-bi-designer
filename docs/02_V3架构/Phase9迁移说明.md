# Phase9 迁移说明

Phase9 将 V3 看板从单页面设计扩展为多页面与受控事件运行时。既有合法 V1、V2 和单页面 V3 数据继续通过原迁移链读取，不要求数据库迁移。

## 数据兼容

- V3 应用至少包含一个页面，并由 `defaultPageId` 指向默认页。
- `activePageId`、事件事务、缓存、运行参数、错误和加载状态均为会话态，不写入 V3 JSON。
- 新事件动作只允许 `setParameter` 与 `refresh`。旧 `dialog` 页面可读取，但不允许新建或复制。
- 页面复制会重建页内实体 ID，并重写复制页内 Refresh 引用；跨页面 Refresh 仍被拒绝。

## 运行方式

事件只在 Designer 的预览模式执行。设计模式中的组件点击、事件配置、保存和导入不会触发动作。预览进入与切页按“取消旧任务、加载当前页、触发唯一 `pageEnter`”执行；组件 click 使用同一预览会话 EventBus。

SetParameter 复用 Phase8 Parameter Store、类型校验、同值去重和依赖刷新。显式 Refresh 复用 Phase8 查询键与缓存，但固定 `force=true`；参数依赖刷新保持 `force=false`。

## 升级与回滚

升级前保留现有 V3 JSON 备份。可使用 [Phase9 示例](./示例/dashboard-v3-phase9.json) 验证多页面、参数动作和显式刷新。

回滚时移除预览运行时接线即可恢复为“只配置、不执行”；P9.1—P9.6 的持久化契约不依赖运行态数据。当前工作仍在隔离分支，未提交、推送或合并。

## 排除范围

页面导航、下钻、弹窗、外链、发布快照、权限和 AI 能力属于后续阶段，不在 Phase9 中迁移或执行。
