# 数据集规模化规划

## 设计原则

数据集数量增长后，不能依赖一个不断变长的下拉框。Designer 只保存稳定的数据集 ID 和字段映射；目录检索、分类、分页和权限由数据集服务负责。

## 配置模型

组件仅保存：

```json
{
  "dataConfig": {
    "sourceKind": "server",
    "datasetId": "dataset-uuid",
    "dimension": "stat_date",
    "field": "is_valid_service"
  }
}
```

数据库密码、Host、SQL 和凭据目标不进入看板 JSON。SQL 保存在数据集服务中，密码保存在本机加密存储中。

## 展示层级

1. 最近使用和收藏。
2. 业务域或主题目录。
3. 数据源筛选。
4. 名称、备注和字段全文搜索。
5. 分页数据集卡片。
6. 数据集详情：字段、类型、说明、负责人、质量状态和更新时间。

## 推荐后续模型

数据集增加以下元数据：

- `domain`：业务域。
- `tags`：标签。
- `owner`：负责人。
- `status`：草稿、已验证、停用。
- `field.label`：字段中文名。
- `field.description`：业务解释。
- `field.unit`：单位。
- `field.defaultAggregation`：默认聚合方式。
- `qualityStatus`：质量状态。
- `usageCount`：使用次数。

组件后续增加：

- 聚合方式：求和、计数、去重计数、平均、最大、最小。
- 单位与数值格式。
- 空值处理。
- 排序和 Top N。
- 时间粒度。
- 数据刷新策略。

## 性能策略

- 目录查询使用服务端过滤和分页。
- 数据集元数据与查询结果分开加载。
- 同一页面多个组件绑定同一数据集时共享一次查询结果。
- 查询设置超时和最大返回行数。
- 后续可增加短期缓存、请求合并和取消过期请求。
