# 组件需求

V3 继续复用 V2 基础组件渲染与配置，不为医疗业务组件建立独立渲染分支。Phase7 的目标是让现有组件通过活动页适配器在 V3 默认页中无回归运行。

## 现有基础能力

- 指标卡、图表、表格和文本拥有分离的专属配置。
- 图表支持多维度、多指标、组合图、双轴、标签和预警线。
- 组件支持八方向缩放、图层、布局坐标、样式和本地持久化。
- 医疗业务组件采用基础组件快照，可保存、分类、重命名和复用。

## Phase7 要求

- 组件模型继续接收现有 V2 数据配置，避免 V3 根模型改造扩散到所有渲染器。
- V3 到当前默认页的转换集中在活动页适配层。
- V2 组件 ID、顺序、位置、图层和专属配置迁移后保持不变。
- 医疗模板在 Phase7 不增加参数契约、事件或导航运行逻辑。
- 气泡图和坐标轴视觉修复作为独立 `UI-FIX-01` 任务，不阻塞 Phase7。

## 后续要求

- Phase8 为组件数据配置增加参数绑定与刷新策略。
- Phase9 为组件增加统一事件绑定，不按图表类型编写联动特例。
- Phase10 开放导航、下钻和弹窗动作。
- Phase11 将医疗模板升级为 V3 参数契约、默认事件和默认导航。

## 验收重点

- 迁移前后组件数量、顺序、位置和配置一致。
- 组件添加、选择、移动、八方向缩放、删除和属性配置无回归。
- Mock 与服务端数据集组件继续正常运行。
- 设计器保存和导入导出统一写 V3，但组件内部不被无关重构污染。
