# Medical BI Designer 文档中心

本目录按“项目规划、V2 基线、V3 架构、需求设计、测试验证、AI 规划”分类。当前入口是 [项目当前状态](./项目当前状态.md)；已完成阶段见 [Phase7 交付说明](./02_V3架构/Phase7交付说明.md) 和 [Phase7 最终验收记录](./04_测试验证/验收记录/Phase7最终验收记录.md)。

正式切换 GitHub 前必须执行 [Release 准备任务](./00_项目规划/Release准备任务.md)，并完成根目录的开源与私有资产清单。

## 目录导航

| 目录 | 内容 | 当前用途 |
| --- | --- | --- |
| `00_项目规划` | 产品路线、V2 后续开发顺序 | 查阅阶段背景与历史决策 |
| `01_V2版本` | V2 开发说明、迁移、样例和历史验收 | 作为 V3 迁移与回归基线 |
| `02_V3架构` | V3 总体架构、数据模型、参数、事件、Phase7 方案与交付 | V3 设计与阶段交付入口 |
| `03_需求设计` | 交互、组件和数据集需求 | 核对产品行为与验收边界 |
| `04_测试验证` | 固定验证环境、验收清单和截图 | 构建阶段验收证据 |
| `05_AI规划` | AI 与智能分析长期方向 | Phase7 不实施，仅保留扩展边界 |

## 当前权威文档

1. [V3 整体架构](./02_V3架构/V3整体架构.md) 定义 Phase7—12 的长期依赖关系。
2. [V3 数据模型](./02_V3架构/数据模型.md) 冻结 V2 到 V3 的模型边界。
3. [参数体系](./02_V3架构/参数体系.md) 区分 Phase7 参数定义与 Phase8 之后的参数运行时。
4. [事件模型](./02_V3架构/事件模型.md) 是 Phase9—10 的预留契约，Phase7 不实现事件运行逻辑。
5. [Phase7 实施方案](./02_V3架构/Phase7实施方案.md) 与 [Phase7 交付说明](./02_V3架构/Phase7交付说明.md) 分别记录已完成阶段的范围门禁与实际结果。
6. [架构现状评审与演进路线](./02_V3架构/架构现状评审与演进路线.md) 是 2026-07-29 的历史架构快照，用于解释 V3 演进依据。
7. [Phase8 实施方案](./02_V3架构/Phase8实施方案.md) 是当前参数运行时与安全查询链路的执行依据。

若整体架构与 Phase7 实施方案存在差异，以 Phase7 实施方案为准。历史 V2 文档只用于解释现状和回归，不覆盖 V3 决策。
