# 跨模型门诊提示词

在设计器顶部点击「提示词样例」。填写业务目标，复制提示词到千问、Gemini、DeepSeek 或其他模型，再将模型最终 JSON 粘回「模型返回 JSON」，点击「校验并添加到设计器」。随后可编辑、保存、重开。

提示词按本地可用月份和样本范围生成，仅包含脱敏指标口径与覆盖范围。不会自动发送数据或调用模型 API。输出示例按钮是本地示例，不能作为模型效果证据。

当前编译结果为5页：上述四页样本链路之外，附加「科室分析 · ADS 数据」，由医院科室前20跳转，支持组合键筛选、月份、趋势与科室目录服务端分页。七字段契约的 pageTitles 仍只命名原四页，保持已有计划兼容。历史已保存看板不自动覆盖，可在看板管理选择「门诊运营分析 · 五页样例」新建验证。

## 可复制业务目标

为医院管理者设计门诊运营分析。医院页呈现月度与累计人次、收入、次均费用、趋势、构成和变化提示；支持医院、科室、医生、明细四页导航。科室与医生局部样本必须明确标识，不能包装为全院排名。缺预算不展示预算，缺同期提示；保留指标口径、来源和明细下载。蓝白配色，启用手机自适应。

## 模型输出契约

```json
{
  "schemaVersion": 1,
  "template": "outpatient-operations",
  "title": "门诊运营分析",
  "month": "2026-08",
  "pageTitles": ["医院门诊总览", "科室分析 · 部分样本", "医生分析 · 部分样本", "医生明细 · 部分样本"],
  "accentColor": "#1477c9",
  "mobileResponsive": true
}
```

只输出这七个字段。月份必须在本地数据范围内且不晚于 2026-08。不得返回 SQL、脚本、指标值、分析结论、Markdown 或思考过程。

这是受控门诊模板的规划契约：模型可以选择月份、标题、配色与移动开关；本地编译器负责指标绑定及配置式交互。当前不能据此生成任意结构的看板。校验错误直接显示，不回退为模板伪装生成成功。

## 千问 32B 验收策略

按 Qwen2.5-32B-Instruct / Qwen3-32B 预留，不从参数量推断实际效果。部署版本、量化、上下文长度和推理服务确定后，使用相同提示词评测合法 JSON 比例、业务约束遵守、导入成功率、延迟和重试次数。建议覆盖正常门诊、缺预算、缺同比、局部医生、非法月份与脚本注入六类目标；保留模型原始最终输出和导入结果，不记录密钥。

Qwen3 使用服务支持的非思考模式，或由服务分离思考与最终 JSON；不要直接拼接思考文本。参考 [Qwen 官方推理文档](https://github.com/QwenLM/Qwen3/blob/main/docs/source/inference/transformers.md)。其他服务可参考 [Gemini 结构化输出](https://ai.google.dev/gemini-api/docs/structured-output) 与 [DeepSeek JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)。即使启用结构化输出，本地业务校验仍必需。

本轮按用户要求跳过真实 API，未对三家模型质量进行比较。
