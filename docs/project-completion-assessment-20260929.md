## 优化顺序

当前收口项：新版医院概览的最终视觉与操作体验尚未记录为用户验收通过。先复检实际显示和演示操作，仅修暴露的高影响体验问题；这不是重新等待知识定义确认。连续 AI 等扩展仍按总计划后置。以下是完成体验收口后的优化建议。

1. **补只读数据更新。** 一个“更新本地数据”入口显示快照采集时间、更新状态和失败原因；成功后刷新依赖看板。保持预算空值和既有参数，避免刷新旧快照却宣称实时更新。
2. **先收口配置体验。** 点击已有规则直接定位触发事件和当前动作；显示中文业务字段名；将“下钻并打开详情”装配成可检查的原生多动作预设。高级编辑继续保留，不添加业务专用运行时回调。验收：用户能从表格一次进入既有规则，修改目标后预览、保存、重开。
3. **补连续 AI 展示调整。** 限标题、色彩、字号、布局等展示字段，沿用预览/应用/撤销与过期冲突保护。当前文字调整是确定性命令，不计为已完成大模型连续编辑。
4. **消除样例和保存状态的体验断点。** 看板管理的医院示例与“打开ChatGPT医院概览草稿”依赖固定历史 requestId 和本机忽略目录内的方案文件；空环境可能打不开。API 新生成流程会创建新请求，不受此历史请求依赖限制。菜单重复创建会产生同名看板。保存成功反馈仅保留 2.6 秒，之后显示“当前草稿”；未保存修改本身已有区分。应改善持续可见的已保存/未保存反馈，不据此推断存储错误。建议模板可复现、打开已有或明确创建副本。
5. **统一验证入口。** 默认 `npm test` 仅覆盖 `tests` 顶层 `.test.ts`；`.test.mjs` 与独立 E2E/Chromium 均需额外入口。新增服务端测试不在 343 项中。应提供包含服务端测试和代表性本地闭环的统一入口，保留原始证据和配置恢复，不将已单独测过等同于默认持续门禁覆盖。
6. **整理候选与计划。** 当前大量改动仍未提交；最新菜单演示和 20 组件视觉状态未完全同步到总计划。整理可复现依赖、忽略本地凭据/状态/证据产物，随后形成可审查候选。合并、推送与发布仍需已有权限边界。拆分 245KB DesignerHome 与 2.07MB 构建 JS 作为后续维护/加载优化，不据包大小直接断言体验已失败。

总计划仍以视觉/操作复检收口为当前边界；之后建议只读快照更新 → 配置体验 → 受限连续 AI 展示调整。配置体验可在当前演示复检中优先处理实际问题，符合 Owner 更重视联动跳转易用性的偏好。第 5、6 项在形成稳定候选时一并收口。暂无证据要求为了知识定义不确定而暂停本地开发。
