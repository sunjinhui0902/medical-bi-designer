## 高风险修复冻结方案

R01/R02 不改 API 数据契约、数据模型、SQL 或看板 V3 Schema。不读取或输出密码，不调用远程服务。存储策略：损坏/权限失败阻止读取修改，缺失文件允许首次创建；临时文件和目标同目录，写完后替换；单进程按文件串行完整读改写。访问策略：只接受回环 Host 和明确本地前端 Origin；无 Origin 的本地工具保留。测试使用临时文件、合成配置与回环 HTTP，不修改项目现存配置。回滚仅撤销本轮模块及引用，不重置既有工作区。

R11：连接参数映射修复，`require` 保留加密但不验证证书；`verify-ca` 验证信任链，`verify-full` 验证信任链和主机名。不改变密码和数据源文件，不连接远程数据库。依据 [node-postgres SSL 文档](https://node-postgres.com/features/ssl) 和 [Node.js TLS 文档](https://nodejs.org/api/tls.html#tlsconnectoptions-callback)。`allow/prefer` 的自动降级协商仍未实现，需后续明确支持范围。

R01 同样适用于知识资产 JSON：复用原子写与同文件串行修改，保存时重新读取资产；损坏文件报错，保留原文件。本轮仅通过临时文件验证存储策略，未修改真实知识资产。
